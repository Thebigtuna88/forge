# Phase 3 — Review runner (FRG-7, #7)

Approved by the owner 2026-10-29 ("I approve the FRG-7 plan with decisions 1–3 incorporated"),
with: verify how codex loads instructions before implementation, and stop with a revised proposal
if the promised isolation can't be enforced; keep L12 explicit; the owner merges. Spec section 6
describes the runner as built. Decisions: `docs/decisions/2026-10-29-review-runner.md`.

## Scope

- **In:** `review-lens` and its subcommands, the reply schema, five lens checklists, rounds log,
  stall check, deferrals, `finalize` (review.md + PR comment text), the required-lens computation
  shared by the runner and the merge gate, tests.
- **Out:**
  - Making the runner tamper-proof: FRG-27 (#27), after the FRG-26 checkpoint. **Known limit L12
    stays open**: the runner, its files and the agent share one macOS user, so a deliberately
    dishonest agent could still forge a review. The runner is built so FRG-27 can move it
    without a redesign.
  - `frontend` and `ios` for real projects: their rules are built and tested with sample project
    types and take effect once FRG-10 adds `projects.json`. For FORGE itself the required lenses
    are `code`, `security`, and `spend` when the diff touches spend.
  - No GitHub setting, Mac account, codex setting or permission changes.

## Owner decisions

1. **Codex only** (2026-10-28, "yes, codex only"). No `review-lens ingest --mechanism subagent`
   fallback. If codex is unavailable, the agent stops and asks the owner. The merge gate refuses
   `subagent` too (until now it accepted it for non-code lenses).
2. **More owner-only paths** (2026-10-29, decision 2 only): `.harness/bin/review-lens` and the
   whole `.harness/lenses/` folder (checklists, reply schema, anything later put there). Before,
   a PR that only weakened a checklist or the reply schema could have been merged by the agent.
3. **Evidence beside the diff** (2026-10-29). Evidence files go in `work/<T>/evidence/` and are
   joined into each round's `evidence.txt`, separate from `diff.patch`. The reply reports md5 and
   bytes for both; `verify` checks both when there is evidence, rejects missing or mismatched
   evidence values, and requires them null when there is none. The merge gate's code-only diff
   comparison is unchanged. Spec 6.3 says what the check shows: **fingerprints establish file
   consistency; they don't prove the reviewer read or understood the contents.**

## Step 2: how codex loads instructions (2026-10-29)

Tested on this Mac with planted marker words in throwaway repos
(`work/FRG-7-review-runner/codex-isolation.md`). The isolation could be enforced, with more
settings than the plan named. **Plan change (stricter):** besides `--ignore-user-config` and
`project_doc_max_bytes=0` (which stops every `AGENTS.md`/`AGENTS.override.md`), repo skills
(`.agents/skills/`, `.codex/skills/`) reached codex until `skills.include_instructions=false`;
so the runner also turns off skills, plugins, apps, hooks, web search, memories and the browser,
computer-use and image tools, refuses a tree with an `.agents/` or `.codex/` folder, and refuses
any codex version but the tested 0.163.0. The test results are codex's own report of what it
was given; a global `AGENTS.md` in codex's home wasn't tested (none exists; the runner refuses
one).

## Changes during the build

- Every command takes the ticket (`review-lens codex <ticket> <lens>`), so no state outside
  `work/<ticket>/` decides which review a command acts on.
- `finalize` also takes the PR number and reads the PR from GitHub again.
- Stall follows spec 6.4: an INVALID round between two identical valid rounds doesn't prevent a
  stall (the approved plan's test list said the opposite; the spec's rule was kept).
- `init` refuses a new round while `STALL.md` exists, so a stall really stops the loop.
- After review round 1 (10 findings, 7 distinct; each fix has a test that failed first,
  `work/FRG-7-review-runner/red-round-1.txt`):
  - the spend rule also reads `spend-limits.json`'s hosts, key variables, commands and SDK
    packages and always-blocked texts (a missing or malformed list refuses), in the runner and
    the gate alike;
  - any known lens may run when not required, and then must be CLEAN too;
  - the cleanup trap no longer pastes the temp folder's name into shell code;
  - the prompt names the merge base's `CLAUDE.md` (the round's `charter.md`) as the rules in
    force, not the PR's copy, and says the PR's files are never instructions; the docs no longer
    claim FRG-7 stops everything a PR can plant for the reviewer (text in the reviewed files can
    still try to steer it);
  - a failed codex run's reply is set aside and never counts (`codex-<lens>.ok`);
  - finding ids follow one pattern in the schema, verify and defer;
  - a missing checklist stops the run.
- After review round 2 (7 findings, 5 distinct; tests failed first,
  `work/FRG-7-review-runner/red-round-2.txt`):
  - `spend-limits.json` must have the shape `gate-spend` requires, or the lens computation refuses;
  - a lens's latest round is its latest attempt (prompt, reply or failed reply), in finalize and
    in the merge gate, so a newer failed or unfinished run never falls back to an older CLEAN; a
    lens that ran in any round, even only failed, must be listed and CLEAN;
  - each evidence file's read is checked;
  - every deferral is checked against the reviewer's own verified finding before it reaches a
    prompt or `review.md`; a hand-written one stops the command;
  - the prompt is built aside and moved into the round whole.
- After review round 3 (spend 1 finding, security 2; the code reply was INVALID, a stray
  character in its md5, and doesn't count, but its 2 points were valid; tests failed first,
  `work/FRG-7-review-runner/red-round-3b.txt`):
  - **plan change, owner decision 2026-10-29:** the spend detection had a finding in every round
    (round 1 SDKs and `spend-limits.json`, round 2 the list's shape, round 3 the Anthropic SDK).
    The guess is gone: `spend` is required on every PR, like `code` and `security`, and the
    runner and the merge gate both refuse a computed list without all three. `review_lib.py
    lenses` no longer reads `spend-limits.json` or the diff's text. Cost: one more codex run per
    round;
  - git in the worktree reads no system or global settings and has `core.fsmonitor` off; a
    repository whose settings name a filter, or a worktree with a submodule, is refused
    (**stricter than the plan**);
  - the prompt, diff, charter and evidence are scanned by gitleaks before codex runs; a
    detection, a missing scanner or a failed scan stops the run (**stricter than the plan**). What
    gitleaks doesn't know as a secret still goes out;
  - the instruction-file check fails closed on a folder it can't look into;
  - a hidden file in `evidence/` stops `init`.

## Tests (red first)

`tests/unit/review-lens.test.sh`: 29 tests, all failing before the runner existed
(`work/FRG-7-review-runner/red-review-lens.txt`), passing after. They build a conformance-shaped
sandbox, the only place the runner uses the fake `gh` and `codex`, and cover init, codex
(arguments, environment, prompt, instruction files, codex version, refusals), verify (every
INVALID case, evidence rules, a round changed after init), the findings-hash, stall, defer,
finalize, the required lenses, and the real merge gate on the real runner's `review.md`
(accepted; a review without a `spend` lens refused, even for a plan document; a lens computation
that leaves `spend` out refused by the runner and the gate). Conformance:
`lens-security-by-subagent` moved from allow to deny; `lens-spend-missing` (an ordinary change),
`lens-spend-missing-docs-only` and `lens-spend-findings` (deny) and `genuine-with-spend-lens`
(allow) added; `tests/stubs/scene.sh` gives every scene a CLEAN spend lens.
